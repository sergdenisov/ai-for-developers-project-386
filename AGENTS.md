# Agent rules

These rules apply to every coding agent. `CLAUDE.md` only imports this file.

## Project overview

Call booking service: `spec/` (TypeSpec API contract), `backend/` (Fastify, TypeScript) and `frontend/` (React,
Vite, Mantine) are separate npm packages; the root `package.json` holds repository-wide tooling only.

## API contract

- Design first: change the API in `spec/main.tsp`, run `mise run generate` and commit the regenerated files with
  the change. It compiles `spec/openapi.yaml` (OpenAPI 3.0.0) and generates from it, with `@hey-api/openapi-ts`,
  the frontend SDK and the backend handler types.
- The generator and its config (`spec/openapi-ts.config.ts`) live in the `spec` package with TypeScript 6: it needs
  the TypeScript compiler API, which TypeScript 7 in `backend` and `frontend` does not ship.
- Contract paths have no prefix; the backend serves them under `/api` (`fastify-openapi-glue`).
- Backend: implement an operation in the `RouteHandlers` object in `backend/src/app.ts`; glue registers its route
  and validates requests from `backend/src/api/generated/openapi.json`.
- Frontend: call the API through the generated `queryOptions` / `mutationOptions` with TanStack Query's
  `useQuery` / `useMutation`.
- API tests start the app with `buildApp({ validateResponses: true })`, which turns any response the contract does
  not declare into a 500.
- The clock is a seam: `buildApp({ now })` takes a `() => Date`, the system clock by default. API tests pass a fixed
  moment and move it; code reads the current moment only through `now`.
- The rules of Slots (Working Hours, Slot Grid, Booking Window, Free Slots, Upcoming Bookings) live in
  `backend/src/slots.ts`, pure functions that take `now` as an argument; handlers call it and format moments with
  `formatOwnerInstant` from `backend/src/owner-time.ts` (`+03:00`, whole seconds). Unit-test new rules there.
- Two Bookings never overlap, whatever their Event Types. `book` in `backend/src/bookings.ts` checks the Slot and
  inserts the Booking in one synchronous step; never put an `await` between the check and the insert, or
  simultaneous requests can book the same time.
- Errors have one shape, `ApiError { code, message, fields? }`. Every operation declares its error responses in
  `spec/main.tsp`; handlers answer them with `reply.code(N).send(apiError(...))` from `backend/src/errors.ts`, whose
  error handler brings Fastify's own errors (request validation, unknown route, anything unexpected) to that shape.

## Checks

- Run `mise run check` before you call a change done. It runs every check, the browser scenarios included, and it
  must pass: CI runs the same command. The pre-push hook runs only `check:project`, without the browser scenarios.
- `mise run check:e2e` builds both packages and runs the Playwright scenarios in `frontend/e2e/` (Chromium) against
  the built backend started with `--validate-responses` and `vite preview`, on ports of their own
  (`frontend/playwright.config.ts`), so the dev daemons can stay up.
- Browser scenarios talk to the real server only: no `page.route`, no mocked responses. One server serves the whole
  run, so a scenario creates Event Types with unique names and ids, never assumes an empty list, and picks its day
  from the calendar, because time is real.
- Run `mise run fix` for safe autofixes (formatting, Markdown, lint fixes).
- Tool versions are pinned in `mise.toml`; git hooks are defined in `hk.pkl`.
- Do not bypass hooks with `--no-verify`.

## Dev servers

- Start the backend and frontend dev servers with `mise run dev`; they run as mise daemons (pitchfork).
- Use `mise daemons status`, `mise daemons logs <name>`, `mise daemons restart <name>` and `mise daemons stop`
  instead of starting servers in your own shell. Daemons: `backend`, `frontend`.

## Rules and exceptions

- Never disable a lint rule or weaken a check to get a change through.
- An exception is narrow (one path and one rule), carries a reason in the config, and needs a human decision.
  Exceptions that hide a security finding also get a review date.

## Files you do not edit by hand

- `.github/workflows/hexlet-check.yml` and `.github/workflows/README.md` are generated by Hexlet; the course forbids
  editing them.
- `package-lock.json` files change only through npm.
- `spec/openapi.yaml`, `backend/src/api/generated/` and `frontend/src/api/generated/` are generated from
  `spec/main.tsp`; change them only with `mise run generate`.
- `CHANGELOG.md`, `version.txt` and `.release-please-manifest.json` are written by release-please from commit messages.
  `CHANGELOG.md` is exempt from rumdl MD012 and from typos (short commit hashes read as misspellings), and the
  manifest from oxfmt (release-please writes it on one line).

## Commits

Write commit messages in [Conventional Commits](https://www.conventionalcommits.org/) format; commitlint checks them
in the `commit-msg` hook and in CI.

A commit that implements a ticket ends its subject with the ticket number, e.g. `feat(frontend): book a free slot (#12)`;
GitHub turns it into a link, so the history shows which commit did which ticket.
